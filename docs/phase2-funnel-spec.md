# 화장품 인플루언서 시딩 퍼널 분석 — MVP 스펙

> 이 문서는 기획서(`docs/기획서.md`)를 **구현 착수 가능한 스펙**으로 정제한 것입니다.
> 기획서가 "무엇을/왜"라면, 이 문서는 "어디까지(MVP 범위) / 어떤 데이터 / 어떤 지표 / 어떤 화면"을 확정합니다.

- 상태: MVP v1 스펙 (초안 확정용)
- 결과물 형태: 스펙 문서 우선 → 이후 코드 착수
- 최종 수정: 2026-07-20

## 0. TL;DR — MVP 한 장 요약

- **만드는 것**: 인플루언서·콘텐츠별 고유 **쿠폰코드 + UTM 링크 발급기**(①)와, 그 코드/링크로 수집된 데이터를 **인플루언서 간 비교 가능한 퍼널 대시보드**(②).
- **핵심 가치(비교)**: "누가 얼마나 팔았나"를 넘어 "**어느 인플루언서가 클릭 대비 구매 전환이 좋은가**"를 상대 비교.
- **MVP에서 안 하는 것**: 이탈 원인 자동 태깅(③), AI 인사이트 리포트(④). → v2.
- **핵심 제약 반영**: 퍼널을 **쿠폰 트랙 / 링크 트랙** 2개로 분리(§4). 노출(impression)은 MVP 측정 대상에서 제외(수기 입력 선택값).

## 1. 목표와 성공 기준

### 1-1. 목표
유통 채널과 무관하게, 자사가 집행한 인플루언서 시딩이 **실제 구매로 얼마나 이어졌는지**를 인플루언서·콘텐츠 단위로 추적하고, **인플루언서 간 상대 성과를 비교**한다.

### 1-2. MVP가 답해야 할 핵심 질문
1. 어떤 인플루언서/콘텐츠가 **클릭당 구매 전환율**이 높은가?
2. (자사몰 한정) 퍼널의 **어느 단계에서 가장 많이 이탈**하는가?
3. 인플루언서 카테고리·팔로워 규모와 전환 성과 사이에 **관계가 있는가?** (예: 마이크로 vs 메가)

### 1-3. 성공 기준 (MVP Definition of Done)
- 콘텐츠 1건에 대해 고유 쿠폰코드 + UTM 링크가 발급되고, 링크 클릭이 이벤트로 기록된다.
- 주문 데이터(쿠폰코드 포함)를 적재하면, 인플루언서별 **클릭→구매 전환율**과 **쿠폰 사용 건수/매출**이 대시보드에 집계된다.
- 자사몰 이벤트가 있는 콘텐츠는 클릭→랜딩→장바구니→구매 **단계별 이탈률**이 보인다.
- 인플루언서 최소 5명 × 샘플 데이터로 비교 뷰가 렌더링된다.

## 2. 범위 (Scope)

| 구분 | 포함 (MVP v1) | 제외 (v2+) |
|---|---|---|
| 발급 | 쿠폰코드 자동 채번, UTM 링크 생성, 클릭 리다이렉트+로깅 | 스토리 링크 스티커 자동 연동 워크플로우 |
| 수집 | 클릭 이벤트(자체), 주문(쿠폰 매칭), 자사몰 GA4/스크립트 이벤트(있으면) | 외부몰(올리브영·쿠팡) 구매 원천 데이터 |
| 분석 | 인플루언서·콘텐츠별 퍼널 전환율 상대 비교 | 이탈 원인 자동 분류, 마이크로 서베이 |
| 산출물 | 대시보드(집계·비교 뷰) | AI 자연어 인사이트 리포트 |

**Non-goals (명시적 제외)**: 완전한 인과 어트리뷰션, 실시간 스트리밍 집계, 다국가/다통화, 권한/멀티테넌시.

## 3. 용어 정의

- **콘텐츠(content)**: 인플루언서가 특정 상품을 홍보한 개별 게시물(릴스/쇼츠/영상 1건). 추적의 최소 단위.
- **쿠폰 트랙**: 결제 시 쿠폰코드 입력으로 구매를 귀속하는 방식. 클릭 없이도 작동, 전 채널 가능.
- **링크 트랙**: UTM 딥링크 클릭 → 세션 기반으로 중간 퍼널을 관측하는 방식. 자사몰 등 자체 스크립트 삽입 가능한 채널만.
- **세션(session)**: 링크 클릭으로 시작된 한 사용자의 방문 흐름. `session_id`로 이벤트를 묶음.
- **어트리뷰션(귀속)**: 하나의 주문을 어느 콘텐츠/인플루언서의 성과로 볼지 결정하는 규칙(§5-3).

## 4. 퍼널 정의 — 2개 트랙

기획서 §5의 현실 제약(릴스·쇼츠 링크 불가, 외부몰 데이터 미제공)을 스펙에 반영해 퍼널을 이원화한다.

```
[측정 가능성]         쿠폰 트랙(전 채널)        링크 트랙(자사몰 한정)
────────────────────────────────────────────────────────────────
노출 impression   △ 수기입력(선택)          △ 수기입력(선택)
클릭 click        ✕ (링크 없음)             ✓ 리다이렉트 로깅
랜딩 landing      ✕                         ✓ 페이지 진입
장바구니 cart     ✕                         ✓ add-to-cart
결제시도 checkout ✕                         ✓ begin_checkout
구매 purchase     ✓ 쿠폰코드 매칭           ✓ 주문 완료
```

- **MVP 측정 시작점 = 클릭**. 노출은 API 없이는 신뢰 불가 → 수기 입력 컬럼으로만 보관하고 전환율 분모에서는 기본 제외(옵션으로 CTR 계산).
- 쿠폰 트랙은 중간 단계가 비어 있으므로, 대시보드에서 "쿠폰 전용 콘텐츠"는 **클릭→구매(또는 쿠폰사용→구매) 요약 지표**만 노출하고 단계별 이탈 차트는 표시하지 않는다(빈 단계로 오해 방지).

## 5. 지표 정의

### 5-1. 단계 전환율 (링크 트랙)
- 랜딩률 = 랜딩 세션 / 클릭
- 장바구니율 = 장바구니 / 랜딩
- 결제시도율 = 결제시도 / 장바구니
- 구매전환율 = 구매 / 결제시도
- **전체 CVR(링크) = 구매 / 클릭**  ← 인플루언서 비교의 1차 지표

### 5-2. 쿠폰 트랙 지표
- 쿠폰 사용 건수, 쿠폰 매출 합계, 평균 주문금액(AOV)
- (클릭이 있는 채널이면) **쿠폰 CVR = 쿠폰 주문 / 클릭**

### 5-3. 어트리뷰션 규칙 (MVP)
1. **1순위 — 쿠폰 매칭**: `orders.coupon_code` → `contents.coupon_code` → 해당 콘텐츠/인플루언서에 귀속.
2. **2순위 — 세션 매칭(자사몰)**: 쿠폰이 없는 주문은, 구매 세션의 유입 `content_id`(UTM)로 귀속. **라스트터치**, 기여 윈도우 기본 **7일**(설정값).
3. 두 규칙이 충돌하면 쿠폰 매칭 우선. 둘 다 없으면 `직접/미귀속`으로 분류.

> MVP는 "정확한 인과"가 아니라 **인플루언서 간 상대 비교**가 목적임을 명시. 어트리뷰션 규칙은 일관되게 적용되기만 하면 비교 목적에 충분.

## 6. 데이터 모델 (정제 스키마)

기획서 §7을 타입·키·관계까지 명시해 확정. (DB: PostgreSQL)

```sql
-- 인플루언서
influencers (
  influencer_id   PK,
  name            text,
  handle          text,           -- @핸들 (플랫폼 계정)
  follower_count  int,
  tier            enum(mega/mid/micro),   -- follower_count로 파생 or 수동
  category        text            -- 스킨케어/메이크업/...
)

-- 상품
products (
  product_id      PK,
  name            text,
  price           int,            -- 정가(KRW)
  channel         enum(자사몰/스마트스토어/올리브영/쿠팡),
  bundle_option   text            -- 구성/사은품 설명 (nullable)
)

-- 콘텐츠 (추적 최소 단위) = UTM/쿠폰과 1:1
contents (
  content_id      PK,
  influencer_id   FK -> influencers,
  product_id      FK -> products,
  platform        enum(ig_reels/ig_story/yt_long/yt_shorts),
  tracking_type   enum(coupon/link/both),
  coupon_code     text UNIQUE,    -- 발급기가 채번 (nullable if link-only)
  landing_url     text,           -- UTM 부착된 최종 랜딩 (nullable if coupon-only)
  utm_content     text,           -- = content_id 식별자와 1:1
  reported_views  int,            -- 노출 수기입력 (nullable, 분석 보조용)
  upload_date     date
)

-- 이벤트 (링크 트랙 관측)
events (
  event_id        PK,
  content_id      FK -> contents,
  session_id      text,           -- 클릭에서 발급된 방문 식별자
  event_type      enum(impression/click/landing/cart/checkout/purchase),
  order_id        FK -> orders,   -- purchase 이벤트만 (nullable)
  ts              timestamptz
)

-- 주문 (쿠폰/세션 귀속의 대상)
orders (
  order_id        PK,
  session_id      text,           -- 자사몰이면 세션 연결 (nullable)
  product_id      FK -> products,
  amount          int,            -- 실결제액(KRW)
  coupon_code     text,           -- 입력된 쿠폰 (nullable) -> contents 매칭 키
  ts              timestamptz
)
```

**핵심 무결성 규칙**
- `content_id ↔ utm_content ↔ coupon_code`는 논리적으로 1:1. 이 고리가 끊기면 귀속 불가.
- `coupon_code`는 전역 UNIQUE(콘텐츠 간 충돌 금지) → 발급기가 보장.
- 캠페인 그룹핑(여러 콘텐츠 묶음)은 MVP에서 **생략**, 필요 시 `contents.campaign_id` 추가로 확장.

## 7. MVP 기능 스펙

### ① 쿠폰코드 / 링크 발급기 (MVP 필수)
- **입력**: influencer, product, platform, tracking_type 선택.
- **처리**:
  - 쿠폰코드 자동 채번 — 규칙 예: `{브랜드약어}-{인플루언서약어}-{랜덤4}` (전역 UNIQUE 보장, 충돌 시 재채번).
  - `link`/`both`이면 UTM 부착 랜딩 URL 생성 — `?utm_source=influencer&utm_medium={platform}&utm_campaign=seeding&utm_content={content_id}`.
  - 단축 리다이렉트 엔드포인트 발급 — 예: `/r/{content_id}`.
- **출력**: content_id, 쿠폰코드, (있으면) 리다이렉트 URL. 인플루언서에게 전달할 안내 텍스트 스니펫.
- **클릭 로깅**: 리다이렉트 엔드포인트 히트 시 `events(click)` 기록 + `session_id`(신규 발급 쿠키/파라미터) → 실제 랜딩으로 302.
- **범위 밖**: 스토리 스티커 자동화, 대량 일괄 발급 UI(단건이면 충분).

### ② 퍼널 대시보드 (MVP 필수)
- **인플루언서 비교 뷰(메인)**: 인플루언서별 행 — 클릭, 구매, **CVR(구매/클릭)**, 쿠폰 매출, AOV. 정렬/필터(카테고리·tier·platform).
- **콘텐츠 드릴다운**: 인플루언서 선택 시 콘텐츠별 지표.
- **퍼널 차트(링크 트랙 콘텐츠)**: 클릭→랜딩→장바구니→결제→구매 단계별 잔존·이탈률.
- **쿠폰 트랙 콘텐츠**: 단계 차트 대신 요약 카드(쿠폰 사용·매출·AOV)만.
- 시각화는 dataviz 원칙에 맞춰 라이트/다크 대응.

## 9. 기술 스택 & 아키텍처 (MVP)

- **백엔드/발급기**: FastAPI (Python). 리다이렉트 로깅 엔드포인트 포함.
- **DB**: PostgreSQL. (로컬 개발은 SQLite로 시작 후 스키마 호환 유지 가능 — 결정 필요, §11)
- **대시보드**: 집계 API + 프런트. MVP는 서버 렌더 또는 단일 페이지 앱 중 택1(§11).
- **이벤트 수집**: 자사몰은 GA4 연동 또는 스크립트 삽입(→ events 적재). 외부몰은 클릭까지만 자체 로깅, 구매는 쿠폰 데이터로 대체.
- **샘플 데이터**: 실데이터 확보 전, 인플루언서·콘텐츠·이벤트·주문 시드 스크립트로 대시보드 검증.

## 10. 로드맵

1. **1차 (MVP)**: 발급기 + 클릭/쿠폰 트래킹 + 비교 대시보드 ← 지금
2. **2차**: 이벤트 수집 파이프라인 정식화 + 자사몰 GA4 연동
3. **3차**: 이탈 원인 태깅(행동 신호 규칙 + 이탈 팝업 서베이)
4. **4차**: AI 자연어 인사이트 리포트(진단→처방 자동 생성)

---

## 11. 열린 결정 사항 (구현 착수 전 확인)

1. **개발 DB**: 로컬 개발을 PostgreSQL로 바로 갈지, SQLite로 시작할지.
2. **대시보드 형태**: 서버렌더(간단) vs SPA(React 등, 인터랙션 강함).
3. **첫 구현 대상 채널**: 자사몰(전체 퍼널 관측 가능) 우선 vs 쿠폰 트랙(전 채널 구매만) 우선.
4. **샘플 데이터로 먼저 대시보드**를 세울지, **발급기부터** 만들지 (로드맵 1차 내 착수 순서).
